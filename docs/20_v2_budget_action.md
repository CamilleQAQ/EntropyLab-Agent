# V2 第三步：预算动作（`search` / 何时停）

日期：2026-11-06
状态：**动作已实现并可消融。结果是明确的权衡：搜索成本减半（27.6s → 13.6s），
但 holdout 掉 1.7 个点（0.9880 → 0.9713）。原因已定位。**

## 1. 这一步解决什么

V2.2 里预算是**超参数**：`--selection-budget 12`，agent 每轮尽量把 12 秒花光。
也就是说"花多少"由人决定，不由 agent 决定。

这一步把"继续找还是提交"变成显式动作：

| 动作 | 含义 |
|---|---|
| `commit(候选)` | 提交当前最优，停止搜索 |
| `keep` | 不更新，停止搜索 |
| **`search(1)`** | 再付一个候选的钱，评估后重新决策 |

每评估完一个候选，策略都要回答一次"还找吗"——这就把预算从配置项变成了决策结果。

## 2. 停止规则（两条，可分别关闭）

| 规则 | 触发条件 | 参数 |
|---|---|---|
| **lead** | 最优 gain 比第二名高出至少 `min_lead` | `--stop-lead 0.02` |
| **patience** | 连续 `patience` 个候选没有刷新最优 | `--stop-patience 6` |

两条都要求至少评估过 `min_candidates = 3` 个候选（避免第一个候选就停）。
如果连一个可行候选都没有，`patience` 到点也会停（Keep）。

## 3. 一个必要的配套：记忆排序

第一次实现时，adaptive 的结果是 **0.8935**（等于 frozen，所有更新被拒）。
原因很具体：

```text
候选按"预估成本"升序 = MPE × 6 → MDE × 6 → FUSION_TIME × 6 → ...
而可行候选出现在 #13、#20、#32
patience=6 在第 7 个候选就停 → 永远看不到它们
```

所以加了 **method memory**：每轮结束后记住"哪个方法拿到了多少 gain"，
下一轮优先试这些方法（价格只作次级排序）。round 0 没有 champion，
用"该方法相对本轮最佳验证分数的差距"初始化记忆。

加了记忆之后，adaptive 从 0.8935 升到 0.9713——**记忆排序是让预算动作可用的前提**。

## 4. 结果（Paderborn，5 个独立划分）

| 策略 | holdout continual | 候选数/轮合计 | 提取秒数 |
|---|---:|---:|---:|
| 全量搜索（V2.2） | **0.9880 ± 0.0195** | 102 | 27.6 s |
| **自适应停止（本步）** | 0.9713 ± 0.0225 | 43.2 | 13.6 s |

逐划分：

| 划分 | 全量 | 自适应 | 全量候选 | 自适应候选 |
|---:|---:|---:|---:|---:|
| 20261104 | 1.0000 | 0.9583 | 102 | 36 |
| 1 | 0.9954 | 0.9491 | 102 | 66 |
| 2 | 0.9537 | 0.9583 | 102 | 39 |
| 3 | 0.9907 | 0.9907 | 102 | 36 |
| 4 | 1.0000 | 1.0000 | 102 | 36 |

**结论：成本减半（−51% 候选、−51% 秒数），精度掉 1.7 个点。**

## 5. 为什么掉点（可定位）

以 seed 20261104 为例：

- round 2 全量搜索里，最优候选是 `FUSION_TIME_SPEC + ExtraTrees`（gain +0.1667，出现在 #20），
  另有 `FUSION_ALL`（+0.1667，出现在 #37）；
- 自适应在 round 2 只评估了 3 个候选（记忆把上一轮的方法排在最前，且特征已缓存、花费 0），
  第一个可行候选 gain +0.2222 就触发 "clear lead" → 停了；
- 结果选了 `FUSION_TIME + ExtraTrees`，holdout 0.9583，而全量搜索选 `FUSION_TIME_SPEC` 得 1.0000。

**根因：最优方法常常比"第一个可行方法"更晚出现。**
"clear lead" 规则只比较当前已看到的候选，看不到后面还有更好的。

## 6. 这一步证明了什么

- 预算动作**机制可用**：agent 真的在决定"继续还是停"，日志里能看到 stop_reason；
- 记忆排序是必需配套，没有它早停会退化成 frozen（可复现）；
- 成本-精度权衡是**真实且可量化**的：−51% 成本换 −1.7 点；
- 现规则**不是最优的**，而且失败模式清楚：过早相信"当前领先"。

## 7. 下一步（若要把它做正）

1. **先试完整个特征族再允许停**：候选按"方法族"成组，lead 规则只在组边界生效
   （避免在 6 个分类器里挑到一个就停）；
2. **带记忆的先验搜索**：不是"上一轮赢的方法优先"，而是"上一轮赢的方法的所有分类器
   先试完"；
3. **把 N09 极端工况纳入诊断**，确认省成本是否以牺牲鲁棒性为代价；
4. 轮次扩到 5–6 个后，才有足够转移（>50）去谈学习停止策略。

## 8. 复现

```powershell
# 全量搜索
python -m entropy_agent.cli continual run ... --criterion guardrail --select --selection-budget 12
# 自适应停止
python -m entropy_agent.cli continual run ... --criterion guardrail --select --selection-budget 12 `
  --search-policy adaptive --stop-lead 0.02 --stop-patience 6
```
