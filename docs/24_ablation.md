# 组件消融实验

日期：2026-11-07
状态：**做了，结果是诚实的“弱证据”**：接地检查在两个任务里抓到 1 个编造数字；
审查员在这批短任务里没有触发；三组条件的任务得分完全相同（1.00）。

## 1. 怎么做的

同一批任务跑三种条件（`scripts/run_ablation.py`，子进程隔离环境变量）：

| 条件 | 开关 | 含义 |
|---|---|---|
| full | 无 | 完整系统 |
| no_grounding | `LAB_DISABLE_GROUNDING=1` | 假设不做数字接地校验、不要求重写 |
| no_reviewer | `LAB_DISABLE_REVIEWER=1` | 审查员一律 accept |

任务：paderborn-baseline、cwru-class-imbalance（各 3 轮、300 秒预算）。

指标：任务得分（8 项过程检查）、实验数、假设数、**未接地假设数**（假设里的数字
在历史里找不到）、**不稳定实验数**（划分 <3 或 std >0.05）。

## 2. 结果

| 任务 | 条件 | 得分 | 实验 | 假设 | 未接地 | 不稳定 |
|---|---|---:|---:|---:|---:|---:|
| paderborn | full | 1.00 | 1 | 3 | 0 | 0 |
| paderborn | no_grounding | 1.00 | 1 | 3 | 0 | 0 |
| paderborn | no_reviewer | 1.00 | 1 | 3 | 0 | 0 |
| cwru | full | 1.00 | 1 | 3 | 0 | 0 |
| cwru | **no_grounding** | 1.00 | 1 | 3 | **1** | 0 |
| cwru | no_reviewer | 1.00 | 1 | 3 | 0 | 0 |

## 2b. 加固版：齿轮任务 × 3 条件 × 3 次重复

齿轮的划分方差大（37 组），才会触发 `UNSTABLE`。同一条件跑 3 次：

| 任务 | 条件 | 次数 | 平均得分 | 未接地假设（合计） | 不稳定实验（合计） | 有审查意见的次第 |
|---|---|---:|---:|---:|---:|---:|
| gear | full | 3 | 1.00 | 0 | 3 | **3/3** |
| gear | no_grounding | 3 | 1.00 | **1** | 3 | 3/3 |
| gear | no_reviewer | 3 | 1.00 | 0 | 3 | **0/3** |

### 这次读出来的三件事

1. **审查员确实在齿轮上工作**：full 条件下 3/3 次都给出了审查意见（`UNSTABLE`），
   关掉之后 0/3——说明这些意见不是摆设，是它算出来的。
2. **但“有意见”没有改变最终得分**：三个条件的任务得分都是 1.00。
   原因很直接——任务级检查只看过程是否合规，不看“有没有采纳审查意见”。
   要证明审查员改变了行为，需要更长的运行（让它有机会因为意见而换做法）。
3. **接地检查的效果很小但一致**：3 次 no_grounding 里出现 1 条编造数字，
   full 是 0 条；和之前 CWRU 上的 1 条一致。

### 诚实的结论

> 消融证明了两个护栏**在运行**（审查员在难数据上 3/3 触发，接地检查拦到过编造数字），
> 也证明了它们**不伤害**正常流程（得分不变）。
> 但**还没有证明它们改变了最终结果**——这需要更长的研究循环，而不是更多重复。

## 3. 怎么解读（不粉饰）

1. **接地检查确实抓到过东西**：CWRU 上关掉之后，有一条假设引用了历史里不存在的数字；
   开着的时候是 0 条。这是唯一可测的差异。
2. **审查员在这批任务上没有触发**：两次实验都是 5 划分、std 很低，本来就没有不稳定结果，
   所以关掉它也不影响分数。**不能据此说审查员没用**，只能说这批任务太“温顺”。
3. **三组得分完全相同**：说明这些护栏没有伤害正常流程（至少在这两个任务上）。
4. **单次运行噪声大**：paderborn 的 no_grounding 第一次跑挂了（空账本），重跑才正常。
   要做可信消融，每个条件至少要重复 3 次。

## 4. 要让结论变强，下一步

| 做法 | 原因 |
|---|---|
| 换成 **gear** 任务 | 它的划分方差极大，容易触发 `UNSTABLE`，才能显出审查员的价值 |
| 每个条件重复 3 次 | 单次运行的偶然性太大（已经遇到一次空账本） |
| 增加一类“诱导造假”的任务 | 例如让目标要求一个明显达不到的分数，观察接地检查是否拦住编造 |

## 5. 复现

```powershell
python scripts/run_ablation.py --only paderborn-baseline,cwru-class-imbalance
```
